Overview

A full-stack demo app built for a Claude Code workshop: inventory tracking, order management, demand forecasting, backlog monitoring, and spending analytics for a fictional factory operation. There is intentionally no database — all data lives in JSON files loaded into memory at server startup, and authentication is fully mocked.

Tech Stack

Two independently-run dev servers, no shared build step, no ORM/DB layer.

Data Flow — a filter change, end to end

The path every view follows when a user touches the global filter bar.

  1. 1
    User adjusts a filter

    FilterBar.vue writes to the shared useFilters singleton — module-level refs, so every component reading them sees the same state instantly.

  2. 2
    The active view reacts

    Each view watch()es the filter refs and re-runs its load function, then calls getCurrentFilters() to translate UI state (e.g. selectedPeriod) into the API's query-param shape (month).

  3. 3
    api.js issues the request

    A URLSearchParams query string is built and sent as an axios GET to http://localhost:8001/api/... — hardcoded, no env-var indirection.

  4. 4
    FastAPI filters in memory

    apply_filters() narrows by warehouse / category / status (skipping any value of "all"); filter_by_month() separately handles month-or-quarter matching against order_date. Filtering works on copies — the loaded lists are never mutated.

  5. 5
    Pydantic validates the response

    Each route's response_model serializes the filtered Python objects to typed JSON before they leave the server.

  6. 6
    Vue re-renders

    The JSON lands in a raw ref (e.g. allOrders, inventoryItems); computed properties derive the chart- and table-ready shapes, and the template updates reactively.

Notable Findings

Things a reader would only catch by tracing calls across the client/server boundary and comparing docs to what's actually on disk — worth knowing before assuming any of these are wired up.

Client calls six endpoints the server never defines

api.js's getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder, and getPurchaseOrderByBacklogItem all target routes that don't exist in server/main.py — every one 404s. The Pydantic PurchaseOrder/CreatePurchaseOrderRequest models are defined but never attached to a route.

Dashboard.vue references a component that doesn't exist

Its template mounts <PurchaseOrderModal> and calls openPOModal()/viewPO(), but no PurchaseOrderModal.vue file exists anywhere in the repo. Clicking "Create PO" / "View PO" on a backlog row throws a Vue "failed to resolve component" warning.

Backlog.vue is fully built but unreachable

It has its own loading state, priority stat cards, and table — but it's never registered as a route in main.js and has no nav link in App.vue. Working code, no path to it.

Reports.vue breaks every convention the rest of the app follows

Options API instead of Composition API, direct axios.get() calls that bypass the centralized api.js client (against two endpoints not even present in api.js), zero i18n coverage, and leftover console.log debug statements.

Documented test count doesn't match what's on disk

tests/README.md and tests/TEST_SUMMARY.md both describe a test_orders.py file (15 tests) and total 51–55 tests. Only 3 test files exist today, totaling 40 tests. Running pytest -v reports 40 passing, not the documented count.

No CI/CD is actually configured

tests/README.md includes an illustrative GitHub Actions snippet under "CI/CD Integration" — but it's documentation only. No .github/workflows/ or any other CI config file exists in the repo.

Hooks are documented but not wired up

.claude/hooks/README.md describes a second hook, user-prompt-submit.sh (a pre-commit lint gate), that doesn't exist on disk — only post-tool-use.sh is present. Neither hook is actually registered, since no .claude/settings.json or settings.local.json exists in the repo.

has_purchase_order is always false

purchase_orders.json is currently an empty array, and nothing in the codebase ever writes to it — so the computed flag on every backlog item can never be true with the current dataset.
